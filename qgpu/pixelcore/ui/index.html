WHAT’S THE CONTRIBUTION?

A dedicated game core.

This is a game-specific state machine and pixel generator compiled into weights. It uses recurrent memory and emits frames directly, rather than interpreting a long sequence of general GPU instructions.

WHAT’S THE LIMIT?

Small, exact, inspectable.

An 8×8 paddle game with three saves to win. Its rules are compiled, not learned. Full Qwen, standalone circuit and replay modes are labeled separately. No real-time speed or worldwide-first claim is implied.

Research, attribution & what runs where

The host supplies buttons, runs model inference, checks the output against a reference, and displays pixel packets. The reference never supplies replacement state or pixels to model mode. Paddle assistance is an external input policy, not model strategy.

Built on Qwenputer’s compiler, with the merge approach developed in qwenGPU. Prior in-model game work includes the Qwenputer Doom-floor-plan raycaster. A pixel game alone is not a new research result.

Research context: Tracr, Tracr-Injection, Synthesis and Verification of Transformer Programs, and current Qwen3.5 documentation. This implementation uses chipformer, not Tracr, and makes no claim of formal verification.
